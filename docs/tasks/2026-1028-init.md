### Goal

1. Deliver the comment-to-DM workflow with one Go process, SQLite and configurable rules.
2. Provide a reproducible demo and state what has been verified.

### Scope

1. [Architecture](2026-1028-plan-start.md#schemas), [verification commands](2026-1029-plan-verification.md) and [release record](2026-1029-plan-release-v0.1.md) each have one source document.
2. Work follows build → local test → deploy → integration test → demo → cleanup. The [README](../../README.md#ai-assisted-development) describes the five-agent workflow and the author's role.

| Stage | Result | State |
|---|---|---|
| Backend | Rule API, persisted runs, deduplication, recovery and optional Jev decisions | Implemented |
| Local verification | Complete simulated flow, concurrent/early replies, duplicates and restart | Passed in worker-1's run |
| Deployment | HTTPS, protected rule API, callback challenge and persistent SQLite | Passed in worker-2's checks |
| Instagram | Unified Login and token obtained; business verification/App Review unfinished | Live flow unverified |
| Jev | Stub tests pass; feature disabled on VPS | Real provider and quality unverified |

<a id="local-verification"></a>

#### Verification

Use the [local walkthrough](2026-1029-plan-verification.md#full-scenario): create a rule → comment → wait → restart → email → link → replay the same events. Expected result: one run, two inbox events and three accepted actions. The [Jev section](2026-1029-plan-verification.md#jev) covers classification separately.

#### Remaining work

1. Review the final documentation and repository access before sharing the GitHub link. The repository was private at the last check.
2. If live integration is resumed, complete Meta access requirements and verify both subscriptions, scoped IDs and the two-account flow.
3. If Jev is enabled, run the synthetic cases and measure false acceptance, misses, latency and cost.

### Decisions

1. Ship a small working system first: one process, one SQLite database and a fixed workflow.
2. Independent tracks run in parallel; dependent work starts after its input is delivered.
3. Local tests, deployment, Meta access and model quality are separate results. A successful challenge proves only endpoint behavior.
4. Commit, push and deployment require the author's authorization.

### Changes

1. Implemented and deployed the MVP; moved reproduction commands into the verification guide.
2. Kept unfinished Meta and Jev checks explicit and removed repeated handoff notes.
