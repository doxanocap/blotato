# A1: локальный сценарий

Go 1.26, SQLite и один процесс. Адаптер подставной: реальные сообщения не отправляются. Сервис слушает только `127.0.0.1:8080`. База по умолчанию `blotato.db`; путь можно задать через `BLOTATO_DB`. Храните файл базы отдельно от Git: в нём есть текст входящих сообщений и email.

Запуск из корня проекта:

```sh
go run ./cmd/blotato
```

В другом терминале:

```sh
curl -sS -X POST localhost:8080/events -H 'Content-Type: application/json' -d '{"platform":"fake","account_id":"brand","contact_id":"person","kind":"comment","event_id":"c1","text":"pricing"}'
curl -sS localhost:8080/runs
curl -sS -X POST localhost:8080/events -H 'Content-Type: application/json' -d '{"platform":"fake","account_id":"brand","contact_id":"person","kind":"message","event_id":"m1","text":"demo@example.com"}'
curl -sS localhost:8080/runs
```

Подождите до 200 мс после каждого события: обработка действий фоновая. В итоге видны три `accepted` в порядке `reply_comment`, `ask_email`, `send_link` и состояние `completed`. Повтор тех же событий не создаёт действий. Для нового прохода используйте новые `event_id`; при активном проходе новый комментарий игнорируется.

Управление исходом подставной отправки до подачи события:

```sh
curl -sS -X POST localhost:8080/fake/outcome -H 'Content-Type: application/json' -d '{"step":"ask_email","outcome":"unknown"}'
```

`step`: `reply_comment`, `ask_email`, `send_link`. `outcome`: `accepted`, `retryable`, `rejected`, `unknown`. Настройка действует на последующие отправки до перезапуска или изменения. `unknown` не повторяется автоматически; `retryable` пока тоже требует ручного разбора и отображается как `failed` с причиной `retryable_no_auto_retry`. `accepted` подтверждает только ответ адаптера, не прочтение.

`GET /runs` показывает состояние каждого действия и классификацию ошибки без текста входящих сообщений, email или секретов. По умолчанию неверный email оставляет ожидание открытым без ответа. Срок ожидания 24 часа после подтверждения вопроса: это допущение приложения, не ограничение Meta. После перезапуска открытое ожидание сохраняется. Отправка, прерванная до фиксации результата, становится `unknown`.

Границы A1: фиксация времени приёма и переход выполняются в SQLite; исходящий вызов вне транзакции. Действия обрабатывает один worker одного процесса; запускать два экземпляра на одной базе пока нельзя, поскольку восстановление помечает чужую незавершённую отправку как `unknown`. Автоматического восстановления `unknown`, UI управления настройками и реальной интеграции Meta нет. Связь раннего ответа с запуском сохраняется до подтверждения вопроса. Внешние ID событий должны быть стабильны внутри платформы, аккаунта и типа события.
